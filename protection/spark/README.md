# Защита BM на бесплатном Spark

Подготовлена к переключению. В Firebase включён Email/Password, созданы шесть аккаунтов и закрытый список доступа; личный вход руководителя подтверждён. Новое пространство базы подготовлено закрытым и без записи из приложения. Сделки ещё не перенесены, рабочая страница ещё не переключена. Оплата не подключается.

## Что делает

- Личный вход по подтверждённой рабочей почте и паролю. Закрытый список доступа привязывает UID к профилю. Менеджер видит свои сделки, отчёты и планы, руководитель — всех. Феликс подключается после получения адреса.
- База проверяет права даже при прямых запросах в обход страницы. Изменение записи атомарно добавляет следующую версию и передвигает указатель. Старая версия недоступна для изменения или удаления из приложения, включая кабинет руководителя. UID и время проверяются правилами, время задаёт сервер Firebase. Администратор Firebase по-прежнему может изменить базу через консоль/Admin SDK; от владельца инфраструктуры журнал не защищает.
- Конфликт одновременного изменения одной записи отклоняется; изменения разных сотрудников сосуществуют. Повтор подтверждённой операции после потери ответа не создаёт ещё одну версию.
- Удаление только руководителем: сохраняется версия с флагом корзины. Восстановление добавляет новую версию с прежними значениями. Все версии остаются в базе, автоматической очистки нет.
- Общий реестр VIN/внутренних номеров предотвращает две продажи с одним идентификатором у разных менеджеров. Отдельная АВ допускается. Номер остаётся закреплённым за первоначальной сделкой даже после отмены/удаления: повторная продажа той же машины требует отдельной проработки жизненного цикла. Внутренний номер: латинские заглавные буквы, цифры, дефис, подчёркивание. Старым записям присваиваются BM-00001 и далее; совпадения по клиенту/сумме не удаляются. Неверно введённые разные идентификаторы одной машины автоматически распознать нельзя.
- Раздельные черновики форм и предупреждение о несохранённом редактировании. Черновики находятся в sessionStorage и не заменяют резервные копии.
- «Скачать резервную копию» в кабинете руководителя выгружает все профили, все версии и реестр идентификаторов в частный JSON. Экспорт не содержит паролей и списка входа. Хранить файл вне публичного репозитория. Автоматических независимых копий на Spark этот пакет не создаёт. До запуска/после важных изменений владелец сохраняет выгрузку отдельно. Восстановление всего снимка выполняет администратор после сверки более новых записей, не кнопка автоматической перезаписи.

Данные поступают через подписку Firebase: повторный опрос интерфейса использует кэш, а не скачивает весь журнал каждые 30 секунд. Накопление истории и выгрузки всё равно расходуют бесплатные квоты. При их исчерпании Spark ограничивает работу; автоматического перехода на платный тариф нет.

## Проверки

В Emulator Suite проверены настоящий вход тестовых пользователей, изоляция профилей, прямые запрещённые запросы, неизменяемость истории, конфликт записи, подмена UID, корзина/восстановление, VIN/номер, отдельная АВ, повтор после потери ответа, выгрузка только руководителем, планы только руководителем и отзыв доступа. Локальный пробный перенос 82 сделок сохранил число продаж и сумму. Эти проверки не заменяют приёмку кабинета владельца перед переключением.

```sh
npm ci --ignore-scripts
npm test
npm run test:rules
```

Для Emulator Suite нужны Node 22+ и Java 21+. Используются только проект demo-bm-protection и вымышленные данные. `BM_TEST_MODULES` может указывать package.json уже установленного набора тестовых зависимостей.

## Подключение

1. Авторизовать официальный Firebase CLI под владельцем проекта bm-avto. При необходимости использовать `firebase login --no-localhost`. Разрешения и пароль сотрудникам не передавать. Приватные файлы `../access.private.json`, `migration.private.json`, `config.js` исключены из Git.
2. Включить Email/Password (уже сделано в этой сессии), добавить `e6082872-ship-it.github.io` в разрешённые домены, проверить защиту от перебора/политику паролей. Не включать платный тариф/телефонный вход.
3. Получить публичный Web SDK config существующего приложения в `config.js`: `export const firebaseConfig = {...};`. Секретные Admin SDK credentials в веб-файлы не включать.
4. Создать аккаунты без паролей и без рассылки: `BM_USE_FIREBASE_LOGIN=1 node admin.cjs --apply provision` либо использовать ADC владельца без этого флага. Доступы выдаются по приватному списку; несовпадение существующей роли останавливает скрипт. Пользователь сам запрашивает установку пароля и подтверждает почту. До включения тестировать владельца на отдельной странице.
5. Проверить текущие правила и другие приложения в проекте. Шаблон оставляет существующий публичный доступ `/data` и `/presence`; их защита — отдельная задача. `/dashboard_test` закрывается: уточнить его назначение до применения. Получить свежую внешнюю копию базы и правил.
6. В согласованную паузу сначала запретить старую запись `/dashboard` и корневую запись. Сохранять старые данные read-only для отката. Правила новой `/spark` должны быть закрыты для посторонних с первого момента создания. Не открывать временную публичную запись для переноса.
7. `BM_USE_FIREBASE_LOGIN=1 node admin.cjs --apply migrate --legacy-writes-locked --owner-ready`: читает свежую базу, сохраняет частную внешнюю копию, создаёт только отсутствующий новый набор данных, сохраняет существующий список входа. Проверяет чтение результата. Старое название компании БМ приводится к уже используемому отображению КТ; финансовые поля не пересчитываются. Пробная локальная копия не используется вместо текущей базы.
8. Применить проверенные правила: `firebase deploy --only database --project bm-avto` из этой папки. Предварительно проверить защищённое чтение владельца в промежуточных правилах. Скопировать в корень публикуемого сайта только `index.html`, `auth.js`, `config.js`, `model.mjs`, `store.mjs`. Остальной код и приватные JSON не публиковать как содержимое веб-корня. Ссылка GitHub Pages остаётся прежней.
9. Проверить вход владельца и одного менеджера, итоги каждого профиля и выбранные месяцы руководителя, отчёт дня, редактирование, черновики, скачивание копии, запрет прямого доступа. Убедиться, что старые вкладки не могут писать. Не объявлять задачу выполненной до проверки рабочей версии.

Сборка страницы из сохранённого исходника protection/legacy/index.html: `python3 protection/scripts/build-web.py --spark` из корня репозитория. Она использует общий код форм `protection/web/guards.js` и `bridge.js`; серверные функции для Spark не требуются.

При проблеме остановить новые записи и сохранить новую базу отдельно. Не откатывать старый снимок поверх более новых сделок и не открывать публичную запись. Сверить изменения после переноса, затем выполнить контролируемое восстановление.
